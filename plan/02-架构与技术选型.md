## 一、分层与依赖方向

单向依赖，**下层不得 import 上层**（`tests/test_engine_guards.py` 以 AST 断言，见 §五）。

```
                    ┌─────────────────────────────┐
                    │ cli.py（参数面 / 退出码 / IO）│
                    └──────────────┬──────────────┘
                                   │
        ┌──────────────────────────┼───────────────────────────┐
        │                          │                           │
   ┌────▼─────┐             ┌──────▼──────┐             ┌──────▼──────┐
   │ ledger   │             │  container  │             │   report    │
   │ 缺陷台账  │             │  mbox/Maildir│             │ JSON + MD   │
   │ 指纹/排序 │             │  切分与变体  │             │ 单一渲染源   │
   └────▲─────┘             └──────┬──────┘             └──────▲──────┘
        │                          │                           │
        │      ┌───────────────────┴──────────────┐            │
        │      │                                  │            │
   ┌────┴──────▼──────┐   ┌──────────────┐   ┌────▼─────────┐  │
   │  scan（字节扫描） │──▶│ attribution  │   │  transfer    │──┘
   │  头块/边界/树     │   │ 归属与引用   │   │  base64 / QP │
   └────────┬─────────┘   └──────▲───────┘   └──────┬───────┘
            │                    │                  │
            └────────┬───────────┴──────────────────┘
                     ▼
              ┌─────────────┐
              │  headers    │  RFC 2047 / 2231 语法
              └─────────────┘

   基础设施（被所有模块 import，自身不 import 业务模块）：
     errors.py（异常与退出码分类）  exit_codes.py（契约常量与判定）  model.py（节点/缺陷数据类）
```

**依赖规则（可机检）**：

| 规则 | 内容 | 判定 |
| --- | --- | --- |
| R-A | `model.py` / `errors.py` / `exit_codes.py` **不得** import 本项目其他模块 | AST |
| R-B | `scan.py` 只可 import 基础设施 | AST |
| R-C | `headers.py` / `transfer.py` / `attribution.py` / `container.py` / `ledger.py` 只可 import 基础设施 + 其下层 | AST 白名单 |
| R-D | `report.py` 只消费 `ledger` 产出，**零判定**（不做规则判定、不重算摘要） | AST 禁 import 业务判定模块 |
| R-E | `cli.py` 是唯一允许写 stdout/stderr 与文件的地方 | AST 扫 `open(` 与 `print(` |
| R-F | 除 `devtools/` 外**全包禁止 `import email`**；全包禁止 `socket`/`urllib`/`http`/`ftplib`/`smtplib` | AST |
| R-G | 全包不得读时钟（`time.*` / `datetime.now`）——输出确定性 | AST |

> R-F 是本题的存在理由（`plan/00` D6）：标准库 `email` 正是被审计对象，用它等于照抄被测方的判断。`mimeconform/devtools/stdlib_compare.py` 是**唯一例外**，只供测试取证，**不得出现在报告路径**（`report.py` 禁止 import `devtools`，AST 断言）。

## 二、字节扫描状态机（scan.py）

引擎是**自写字节级状态机**，不借助任何 MIME/邮件解析库。输入是 `bytes`，输出是节点树。扫描顺序固定，保证 `tree_digest` 可复现。

```
状态： HEADER_BLOCK ──空行──▶ BODY
                    │
                    ├─ 见 Content-Type: multipart/*; boundary=B ──▶ 进入 PART_BODY(B)
                    └─ 见 message/rfc822 ──▶ 递归（内层 is_message=True）

PART_BODY(B) 逐行扫描（按 CRLF / LF 双形态切行，行界保留原始偏移）：
  line == "--" + B          → part 开始（前一 part 结束）
  line == "--" + B + "--"   → multipart 关闭（close-delimiter）
  line.startswith("--" + B) 但不是上述两形态 → MC-B04 候选（形态错误）
  line.startswith("--") 且未在任何 B 上命中 → 可能是 delimiter 不在行首（MC-B03）
  其余行                      → 归入当前 part 的字节区间
```

**行界判定**：`\r\n` 与裸 `\n` 都接受；`offset` 一律按**原始字节**计，不做解码、不做 `str` 化（避免字节↔字符漂移）。行首判定以 `\n` 之后的第一字节为准。

**嵌套复用同一 boundary**（RFC 2046 §5.1.1/§5.1.2，MC-B06 `hard`）：检测到子部件 `Content-Type` 的 `boundary` 与任一祖先相同时，**不选边**，产出两棵候选树：
- `tree_a`：内层先闭合（close-delimiter 归最近的内层）
- `tree_b`：外层先闭合（close-delimiter 归最近的外层）
两树差异以 `divergence` 字段给出（首个分歧的 `path` + `offset`）。这是 `plan/00` D9，也是 cpython #69914 的形状。**默认 `tree` 字段 = `tree_a`，但报告必须显式声明"默认展示不构成判定"**。

**preamble / epilogue**：分别登记起止偏移，**不计入** `body_sha256`（`plan/01` M1 确定性纪律）。

**深度**：`--max-depth` 默认 `32`（`data/README` §7.6）；超限记 `gray/note` 并**停止下钻**（不是崩溃、不是静默截断——登记 `truncated: true` + 偏移）。

## 三、头块解析（headers.py）

输入是**原始头块字节**（未解码、未折叠展开），输出 `headers[]`：

| 字段 | 说明 |
| --- | --- |
| `name` | 头名（原样，不折叠大小写；比较时按 ASCII 小写） |
| `raw_value_sha256` | 值字节（含折行，去尾部 CRLF）的摘要 |
| `octets` | 值字节数 |
| `encoded_words[]` | `{token_start, token_end, charset, encoding, text, length}`（长度按**编码后 ASCII 字节**计，`plan/01` M2 纪律） |
| `params[]` | `{name, value, extended(bool), segments[], charset, language}` |

**折行**：以 `LWSP` 开头的行为续行，拼接时**保留原始字节**并同时记 `line_spans[]`（供 `offset_kind="line"` 的规则精确到行）。**不在此层展开 encoded-word**——展开属 `attribution` 的取值环节（顺序见 `data/README` §7.5）。

## 四、传输编码（transfer.py）

自写 base64 / QP 编解码，**不引第三方、不 import base64**？——`base64` 属标准库且**不是被审计对象**（被审计的是 `email` 包），可用；但为满足"字母表外字符按 RFC 忽略并计数"（`foreign_chars`）与"非法填充要定位到偏移"，**默认走自写解码器**，`base64` 仅用于测试端的交叉校验（`tests/` 内）。

| 函数 | 语义 |
| --- | --- |
| `observe_body_shape(body: bytes) -> Shape` | 不依赖声明，按字节给出 `observed_shape`：`text` / `base64` / `qp` / `binary` / `empty` |
| `decode_base64(body, strict=False) -> (bytes, Base64Facts)` | 忽略字母表外字符并计数；填充与长度问题记入 facts，**不抛异常** |
| `decode_qp(body) -> (bytes, QpFacts)` | 非法 `=HH` 记入 facts 并**原样保留该字节**（不吞字符） |
| `qp_lines(body) -> LineFacts` | 行宽（octets，不含 CRLF）、软换行位置 |

**交叉校验（MC-T01）**：`declared_cte` 与 `observed_shape` 不一致 → `diff`，`rfc = "none-by-design"`，**永不 `hard`**（`plan/00` D2）。

## 五、归属与引用（attribution.py）

| 步骤 | 内容 |
| --- | --- |
| 1 | 为每个叶节点取 `filename`：**先 RFC 2231（含续行合并）→ 再 RFC 2047**（`data/README` §7.5，D10） |
| 2 | 判定 disposition：`attachment` / `inline` / 缺失 → `undecidable` |
| 3 | `cid` 收集：`Content-ID` 头（去尖括号比较，**不 URL 解码**）与正文里的 `cid:` 引用做双向闭合检查 |
| 4 | `multipart/related` 的 `start` / `type` 与实际首部件比对（`start` 缺省时取第一个子部件） |
| 5 | `message/rfc822` 的内层头与归属（转发体） |

**全部规则 `diff` / `gray`，无 `hard`**（`plan/00` D11）。

## 六、容器层（container.py，可选模块 M5）

| 变体 | 规则（`data/README` §7.7） |
| --- | --- |
| `mboxo` | `From ` 行即分隔行；`>From ` 保留不反转义 |
| `mboxrd` | `>From ` 反转义为 `From `；`>>From ` 保持一层 |
| `mboxcl` | 优先 `Content-Length` 切分，缺失回落 `mboxo` |
| `auto` | 纯字节规则（§7.7 写死），只决定"主表"是哪一份 |

**所有变体的切分表都写入 `split_variants`**；`offset_kind = "message-relative"`（容器层），文件级偏移另记 `file_offset`。

## 七、台账与报告（ledger.py / report.py）

**六元组**（`plan/01` §二）在 `model.Defect` 上落成字段；`ledger.py` 负责：

1. **去重与顺序**：按 `(rule_id, path, offset)` 升序；同字节双记由规则层互斥（`data/README` §7.5）保证。
2. **`rfc` 非空校验**：空值即 `AssertionError`（构建期/运行期都失败，D8）。
3. **`class` 三值校验**：集合外即失败（D7）。
4. **指纹**：`fingerprint` 与 `tree_digest`，算法按 §7.8 **逐字实现**（`json.dumps(..., ensure_ascii=True, separators=(",", ":"))`）。
5. **渲染**：`report.py` 只做格式化——同一份 `Ledger` 同时渲染 JSON 与 MD，**同源**（不是两套代码各算一次）。

**报告头**必须含：输入的基础事实（文件名、字节数、`sha256`）、工具版本、`class` 计数、`none-by-design` 计数、退出码、以及一句"本报告是结构层判定，不是解码器 / 不含任何认证语义结论"。

## 八、退出码契约（接线）

| 码 | 语义（唯一定义见 `data/README` §7.9） | CLI 落点 |
| --- | --- | --- |
| 0 | 审计完成，无 `blocker`/`major` | `audit` 正常返回 |
| 1 | 用法错误或输入不可读 | `argparse` 错误映射、文件不存在/不可读、`selftest` 失败 |
| 2 | 审计完成，存在 `minor`（无 `blocker`/`major`） | `audit` 返回 |
| 3 | 审计完成，存在 `major`/`blocker` | `audit` 返回 |

**实现要点**：`argparse` 对未知子命令/缺参数抛 `SystemExit(2)`，**与本题的 2 语义冲突**（2 = 有 minor）。故 `cli.main()` **统一捕获** `SystemExit`：`code == 0` → 0（`--help`），其余 → `1`（用法错误）。判定逻辑集中在 `decide_exit_code(defects, fail_on)`，不做第二套。

## 九、确定性设计

1. **无时钟、无随机、无环境**：输出中不得出现时间戳、绝对路径、主机名、耗时（AST 守门 R-G）。
2. **字节优先**：所有位置按字节偏移计；行的判定按 `\n` 切分而非 `str.splitlines()`（后者会额外切 `\r`、`\x0b`、`\u2028`）。
3. **排序唯一**：缺陷 `(rule_id, path, offset)`；节点按 `path` 分段整数比（`0.10` 排在 `0.9` 之后）。
4. **JSON 序列化唯一入口**：`ledger.dumps()` 一处；`ensure_ascii=True`、`separators=(",", ":")`、`sort_keys=False`（键序在 dataclass 字段序上固定）、结尾**一个** `\n`。
5. **双跑逐字节一致**：`tests/test_determinism.py` 对每个 golden case 跑两遍并 `cmp`。
6. **stdout 编码**：入口 `_ensure_utf8_stdio()`（按 `stream.encoding` 探针，UTF-8/cp936 不动，其他 `reconfigure`），保证 CI 管道 cp1252 下不崩。

## 十、构建与技术选型

| 项 | 选择 | 理由 / 备选 |
| --- | --- | --- |
| 语言 | Python **3.11+** | 需要 `match`、内置 `tomllib`（读 `catalog.json` 之外的元数据）、`dataclass(slots=True)`。**下限 3.11 要落成 AST/运行时断言**（CI 矩阵 3.11/3.12/3.13）。 |
| 运行时依赖 | **零第三方** | 审计引擎只用标准库（且不用 `email`）。CI 用 `--network none` 容器证明"无安装步骤也能跑"。 |
| 构建后端 | `setuptools`（PEP 621） | 生态默认、sdist/wheel 双形态均可用。`MANIFEST.in` 白名单覆盖 `mimeconform/rules/*.json`。 |
| 分发 | `pipx install` / `python -m mimeconform` / 裸 `mimeconform` | **三条通路都要在 CI 冒烟**（`python -m` 与 console script 的 `sys.path` 来源不同）。 |
| 测试 | `pytest`（dev extra） | 只进 `[project.optional-dependencies].dev`；运行时不引入。 |
| 静态门 | 自写 AST 脚本 + 布局门/脱敏门 | 不引 `ruff`/`mypy` 以免"零依赖"承诺在开发面打折；需要时只进 dev extra。 |
| 文档产物 | 纯 Markdown | 无常驻渲染依赖；`--out` 只写指定路径。 |

**构建顺序（发布期硬纪律）**：交付面定稿（README 状态行 / 版本号）→ 重生成 golden → 全量测试 → `rm -rf dist build` → `python -m build`（在 `git archive <tag>` 导出树里）→ 双装态验证 → `SHA256SUMS` → tag → Release。

## 十一、发布形态（M6）

| 项 | 决定 |
| --- | --- |
| 仓库 | GitHub 公开仓库 `10-27-mimeconform`，署名 `yuluo554` |
| 附件口径 | **手工源码包**：`git archive --format=tar --prefix=mimeconform-<ver>/ <tag> \| gzip -9n`（可复算：同命令再跑一次 `cmp` 逐字节一致）+ `SHA256SUMS` |
| 理由 | 无构建步骤的纯 CLI 审计项目，源码包即交付物；相比 sdist，`git archive` 的字节不受 setuptools mtime 影响，**可复算**。 |
| 不做什么 | 不发 wheel（会与"规则包随源码可查"的叙事分裂）；不提供 `--online` 之外的网络能力（本工具零网络）。 |
