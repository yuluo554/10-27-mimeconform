# 03 · 模块详设 — 10-27-mimeconform

> **性质**：M0 收尾产出。**规则编号语义 / `class` / 严重度 / 退出码 / 指纹算法**只在 `data/README.md` §七定义；本文只写**接口、判定条件、假阳/假阴风险、验收点**。
> **编号消歧**：本文的 `scan` / `headers` / `transfer` / `attribution` / `container` / `ledger` 是**代码模块**；`plan/01` 的模块 M1–M5 是**功能面**；`plan/05` 的 M0–M6 是**里程碑**。三者不同。

## 零、公共数据模型（`model.py`）

```python
@dataclass(frozen=True, slots=True)
class Defect:
    rule_id: str          # MC-<域><两位>，语义见 data/README §7.2
    klass: str            # "hard" | "diff" | "gray"（序列化为 "class"）
    severity: str         # blocker | major | minor | note
    path: str             # 树路径，见 §7.3；容器层 "msg#3"
    offset: int
    offset_kind: str      # absolute | message-relative | line
    rfc: str              # 不得为空；无条款写 none-by-design
    detail: str
    related: tuple[str, ...] = ()   # 被互斥规则压掉的 rule_id
```

```python
@dataclass(frozen=True, slots=True)
class Node:
    path: str
    content_type: str          # 小写主类型/子类型；无法判定时 "application/octet-stream"
    boundary: str | None
    headers: tuple[Header, ...]
    body_range: tuple[int, int]
    body_sha256: str
    children: tuple["Node", ...]
    truncated: bool = False
```

**不变量**（`tests/test_model.py` 断言）：
- `klass ∈ {"hard","diff","gray"}`；`severity ∈ {"blocker","major","minor","note"}`
- `rfc` 非空且非 `""`、非 `" "`
- `offset >= 0`；`offset_kind ∈ {absolute, message-relative, line}`
- `path` 匹配 `^(msg#\d+/)?\d+(\.\d+)*$`

## 一、`scan.py` — 树与边界

**入口**：`scan_message(data: bytes, *, max_depth: int = 32) -> ScanResult`

`ScanResult`：`root: Node`、`tree_alternatives: tuple[Node, ...]`、`divergence: Divergence | None`、`defects: list[Defect]`、`facts: dict`。

| rule_id | 判定 | class | severity | rfc（§三 台账行） |
| --- | --- | --- | --- | --- |
| MC-B01 | `multipart/*` 缺 `boundary` 参数 | hard | blocker | RFC 2046 §5.1.1（R6，全录） |
| MC-B02 | `boundary` 字符串 > 70 字符（不含前导 `--`） | hard | minor | RFC 2046 §5.1.1（R6，全录） |
| MC-B03 | delimiter 未出现在行首 | **note** | note | RFC 2046 §5.1.1（R7 该子项**未录** → 门禁降级） |
| MC-B04 | close-delimiter 形态错误（`--b--` 后除可忽略 LWSP 外还有内容） | **note** | note | 同上 |
| MC-B05 | 缺 final boundary | diff | note | `none-by-design`（RFC 无恢复规程；§四.1） |
| MC-B06 | 嵌套复用同一 boundary | hard | major | RFC 2046 §5.1.1/§5.1.2（R7 嵌套子项全录） |
| MC-B07 | 存在 preamble | **note** | note | RFC 2046 §5.1.1（R7 该子项未录 → 降级） |
| MC-B08 | 存在 epilogue | **note** | note | 同上 |
| MC-B09 | 嵌套深度 > `--max-depth` | gray | note（`--strict-depth` 时 minor） | `none-by-design`（§7.6） |
| MC-B10 | `multipart/*` 无任何 body part | **note** | note | 依据只有 stdlib 的 `MultipartInvariantViolationDefect` 实现事实，**无明文条款** → 门禁降级 |

> **原句门禁（机械）**：MC-B03/B04/B07/B08/B10 在 `data/rfc-ledger.json` 对应键 `verbatim` 为空，因此 `catalog.json` 里这五条的 `class` **只能是 `note` 级**，`class` 字段填 `diff`（因为"RFC 未留原句"不等于"有硬规则"），`severity = note`。**补齐原句后才允许提升**（同提交改 catalog + ledger + 测试）。

**假阳风险**：
- boundary 比较**按字节**、不折叠大小写（`plan/01` M1 纪律）。大小写不同的 boundary 是**真的不同**。
- 行首判定在 `\n` 之后；文件首行也算行首。`--b` 出现在行中间不报 MC-B03（那是正文内容）。
- 内容里恰好有 `--` 开头的行但不是任何合法 delimiter → **不报**（无法区分正文与"错的 delimiter"，报就是误报）。只在**已进入某 multipart 且该行匹配某 ancestor boundary 前缀**时才判 B03。

**MC-B05 × MC-B06 的互斥口径（M2 落地时新增，§7.5 第 6 条未覆盖）**：
嵌套复用 boundary 时，**父** multipart 不再登记 MC-B05。理由：那时父级的 close-delimiter 归属
本身有歧义（`divergence` 已声明），再报"缺 final boundary"等于对同一段字节给出两条互斥结论 ——
与 §7.5"同一字节不得双记"的立意冲突。实测见 `data/golden/b-inner-dup/`：只出 MC-B06 一条。
非复用场景下 B05 照常（`b-no-final`），落点 = 片段被迫结束的字节偏移。

**验收**：
- `data/golden/b-inner-dup/`：MC-B06 `hard/major` + `tree_alternatives` 长度 = 2 + `divergence.path = "0.1"`。`stdlib_compare` 按 **M1 实测**写：3.12.10 报 **1 条 `StartBoundaryNotFoundDefect`** 且把内层 `multipart/alternative` 当作非 multipart（即 #69914 的"忽略内层 boundary"）——**不是**"标准库 0 defect"（首稿措辞已按实测修正，见 `HANDOFF-M2` §二.5）。
- `data/golden/b-no-final/`：MC-B05 `diff/note` + 报告写明"树在第 N 字节被迫闭合"；退出码仍 0。
- `data/golden/b-clean-nested/`：0 缺陷（负例）；`data/golden/b-wrapped-header/`：0 缺陷且切出 2 个子部件（负例）。

## 二、`headers.py` — RFC 2047 / 2231 语法

**入口**：`parse_headers(raw_header_block: bytes, base_offset: int) -> HeaderBlock`

| rule_id | 判定 | class | severity | 依据 |
| --- | --- | --- | --- | --- |
| MC-H01 | encoded-word 长度 > 75（按编码后 ASCII 字节） | hard | minor | R1 全录 |
| MC-H02 | 含 encoded-word 的头行 > 76 | hard | minor | R2 全录 |
| MC-H03 | encoded-word 内部出现空白（非折行） | hard | minor | R3 §2 子项（R1 同节） |
| MC-H04 | Q 编码语法非法（`=HH` 不合法 / 字面含 `= ? _`） | **note** | note | R4 §4.1 **未录** → 降级 |
| MC-H05 | B 编码长度非 4 的倍数 | **note** | note | R4 §4.2 **未录** → 降级 |
| MC-H06 | encoded-text 跨 encoded-word 续写 | hard | major | R4 §5 全录 |
| MC-H07 | 头行 > 998 octets | hard | major | R5 全录 |
| MC-H08 | 头值含未编码非 ASCII 字节 | diff | note | `none-by-design`（RFC 2047 是机制不是禁令） |
| MC-H09 | RFC 2231 续行编号跳号 / 前导零 | **note** | note | R10 **未录** → 降级 |
| MC-H10 | `charset'language'value` 缺单引号 | **note** | note | R10 **未录** → 降级 |
| MC-H11 | `%HH` 转义非法 | **note** | note | R10 **未录** → 降级 |
| MC-H12 | encoded-word 内部含折行 | diff | note | `none-by-design`（§四.5）；与 MC-H03 **互斥**（先判 H12，命中则 H03 进 `related`） |

**判定顺序（§7.5 第 1–2 条，写死）**：头块切分 → MC-H07（行 > 998）→ MC-H12（跨行）→ MC-H03（内空白）。**同一字节不得双记**。

**假阳风险**：
- encoded-word 长度按**字节**计；`=?UTF-8?B?...?=` 里 base64 折行属 MC-H12 而非 H01。
- 头名与值之间的 `:` 后空白不计数。
- `=?` 出现在**非 encoded-word 位置**（如正文、注释）不判——只解析完整 `=?charset?enc?text?=` 形态且 charset 合法（`[!-~]+`，RFC 2047 §2 形态）。

**验收**：`h-2231-seq`（MC-H09 + 修正提示文本，不自动改文件）、`h-ew-newline`（MC-H12 且 `related` 含 MC-H03，`no double record`）、`h-clean-folded`（0 缺陷）。

> **M3 落地口径（2026-10-28，实现后回填；判据未变，只把实现取的那些"边界决定"写清）**
>
> 1. **入口**：`parse_headers(raw_header_block, base_offset=0, *, path="0")` —— 从 `Node.headers[i].line_spans`
>    取回头块字节后独立解析（落法 ①，见 §二.6）。行切分在 `headers` 内部有一份与 `scan.split_lines()`
>    语义等价的实现（分层不允许 `headers` import `scan`），二者由
>    `tests/test_golden_engine_headers.py::test_line_splitter_matches_scan` 交叉断言。
> 2. **`offset_kind="line"` 的口径**：头块内行号（从 1 起，§7.10）。对根部件它与文件行号相同；
>    嵌套部件上是块内行号。
> 3. **2231 判定只在可带参数的头（`Content-Type` / `Content-Disposition`）上跑**：正文里的
>    `; a=b` 形态不是参数，对它判 2231 会把普通文本误报成参数缺陷。
> 4. **H09 的"缺 `*0`"子项**：`name*=`（扩展形态但无编号）记为 MC-H09（SO 44154520 的形状）。
>    RFC 2231 §4 允许单段 `name*=`，但本题按"缺 `*0` 序号"登记 —— R10 整行未录 ⇒ 只能 `diff/note`，
>    是**登记事实**而非"违规"判定；若审阅者要求更保守，开关是删掉 H09 的该子项（同轮改 golden 与本文）。
> 5. **H12 优先于 H03 的范围**：折行 token 上跳过 H03/H04/H05（同一字节不双记），被压掉的只记 H03 进 `related`。

## 三、`transfer.py` — CTE

| rule_id | 判定 | class | severity | 依据 |
| --- | --- | --- | --- | --- |
| MC-T01 | 声明 CTE 与实际形态不符 | diff | note | `none-by-design`（§四.3，**永不 hard**） |
| MC-T02 | base64 填充非法 | **note** | note | R9 该子项未录 → 降级 |
| MC-T03 | base64 长度非 4 的倍数 | **note** | note | R9 该子项未录 → 降级 |
| MC-T04 | base64 出现字母表外字符 | **note** | note | R9 全录（"须被忽略"→ 出现本身**不违规**） |
| MC-T05 | QP 编码行 > 76 | hard | minor | R8 全录 |
| MC-T06 | QP 软换行误用/破坏 | hard | minor | R8 全录（行末 `=`） |
| MC-T07 | QP 非法转义（`=` 后非两位 hex） | hard | major | R8 同节（软换行定义蕴含 `=` 的唯一合法语义） |
| MC-T08 | 未知 CTE 取值 | diff | note | `none-by-design` |
| MC-T09 | 7bit/8bit 行 > 998 octets | **note** | note | R11 **未录** → 降级 |
| MC-T10 | 未声明 CTE 但正文含 8bit 字节 | **note** | note | R11 **未录** → 降级 |
| MC-T11 | QP 二次编码残留（解码后仍见 `=3D` / `=HH`） | diff | note | `none-by-design` |

> **MC-T07 的条款论证要写进 `docs/defect-catalog.md`**：R8 全录了"行末 `=` = 软换行"，这条把 `=` 的**唯一合法语义**限定为"软换行或 `=HH`"。`=u` 两者都不是 → 违反 §6.7。这是**推导**而非逐字原句——`docs/` 必须同时写出推导链与"若审阅者认为应更保守，降为 diff 的开关在哪"，保持可复核。

**假阳风险**：
- `=3D` 在**编码态**正文里是合法的（表示 `=`）。MC-T11 只在**解码后**仍出现字面 `=3D` 时报。
- base64 里 76 列折行是合法的（R9 的"行 ≤76"子项未录 → 不判），故**不报**。
- QP 行宽按 octets、不含 CRLF。以 `=` 结尾的行按软换行处理，其宽度**不计入**下一行。

**验收**：`t-qp-artifact`（MC-T07 `hard/major` + 字节偏移）、`t-b64-len`（MC-T03）、`t-cte-mismatch`（MC-T01 `diff` + 退出码不变）、`t-clean-b64` / `t-clean-qp`（0 缺陷）。

## 九、规则目录（`rules/catalog.json`）

```json
{
  "schema_version": 1,
  "rules": [
    {
      "rule_id": "MC-B01",
      "module": "scan",
      "klass": "hard",
      "severity": "blocker",
      "rfc": "RFC 2046 §5.1.1",
      "ledger_key": "RFC2046-5.1.1",
      "detector": "scan.no_boundary",
      "summary": "multipart/* 缺少 boundary 参数"
    }
  ]
}
```

**构建期门禁（`mimeconform/rules/__init__.py: load_catalog()` + `tests/test_catalog_gate.py`）**：
- 每条规则的 `ledger_key` 必须在 `data/rfc-ledger.json` 中存在；`rfc = none-by-design` 的规则写哨兵键
  `none-by-design`，它解析成"键存在、原句为空"（与其它降级走同一条判据，不是豁免）；
- 若 `klass == "hard"`，该键的 `verbatim` 必须非空；
- 若 `verbatim` 为空，该条 `klass` 只能是 `diff`/`gray` **且** `severity == "note"`；
- 语义层规则集（`MC-T01`、`MC-A*`、`MC-C*`、`MC-H08`、`MC-H12`、`MC-T08`、`MC-T11`、`MC-B05`、`MC-B09`）**断言 `klass != "hard"`**。

> 这条门禁是"台账没原句 → 代码里报不了 hard"的机械实现（`plan/00` D12、锚点 #10）。
